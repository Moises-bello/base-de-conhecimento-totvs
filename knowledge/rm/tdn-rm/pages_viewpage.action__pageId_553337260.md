*O Roadmap deve ser revisado a cada Release.*

### Portfólio for JIRA

Para auxiliar o ***Product Owner,*** ***Product Manager*** e ***Tribe Lead*** na montagem do *Roadmap* há a ferramenta ***Portfólio for JIRA***, que contribui para o planejamento dos itens nos *Releases*, conforme o tamanho e priorização de cada item.

Na ferramenta ***Portofólio for JIRA***, devem ser criados planos para planejar as entregas do *Backlog* na linha do tempo. É possível criar um plano para cada projeto/*board*, ou unificar mais de um *board* para que se possa ter o planejamento integrado considerando dependências entre projetos.

Principais ganhos na utilização do Portfólio

* Maior visibilidade entre os projetos e as equipes;
* Visão geral das demandas (Nível granular ou mais elevado);
* Acompanhar as metas de negócio;
* Possível replanejamento criando cenários:  
  + Movendo as *issues* para diferentes versões;
  + Alterando o planejamento das entregas;
  + Repriorizando as demandas.
Conceitos Portfólio

**Plano:**

* Contém informações de *issues*, equipes e *Releases* e permite o planejamento de um cronograma das entregas com base nos R*eleases* ou *Sprints **(para equipes que utilizam Sprints para o planejamento de entregas)***.
* Os Planos devem ser ajustados na medida em que é adquirido o conhecimento do *Backlog* e das estimativas. O Plano é utilizado para realizar o planejamento e caso faça sentido pode ser efetivado.

**Programa:**

* É uma visualização de alto nível que auxilia no acompanhamento do *status* e o progresso de vários planos.
* Os programas permitem que você veja como as entregas e as liberações estão alinhadas no fluxo de trabalho e na linha do tempo.
* Programas oferecem uma visão de alto nível do trabalho em vários planos, e exibe apenas dados que estão agregados nos Planos e que estão confirmados no Jira.

**Temas:**

* Os temas são utilizados apenas no Plano e podem auxiliar as visualizações da previsão das entregas.
* *“São áreas de atenção altamente estratégica, fluxos de valor ou categorias de investimento usadas para estabelecer prioridades e definir onde as equipes dedicarão a maior parte do tempo.” **Atlassian***

Etapas do Planejamento

1. **Organize** seu *backlog*:

* + **Priorize** as demandas;
  + **Mantenha** o *board* organizado;
  + **Defina** os marcos já acordados;
  + **Defina** as datas das *releases*.

2. **Crie** o Plano: **[Instrução de Trabalho - Como Criar um Plano no Portfólio for JIRA?](http://tdn.totvs.com/pages/viewpage.action?pageId=458767786)**

* + **Selecione** o *Board* da *Squad*;
  + **Inclua** o Projeto Iniciativa;

3. **Configure** as *Squads*: **[Instrução de Trabalho - Como Criar um Plano no Portfólio for JIRA?](http://tdn.totvs.com/pages/viewpage.action?pageId=458767786)** *- Tópico "Como definir a velocidade do time?"*

* + Velocidade.

4. **Defina** restrições:

* + Datas;

    As restrições de datas serão definidas para os *Epics* ou *Stories*:

    ***Earliest Start*****:** Data início mais antiga

    ***Due date*****:** Data Vencimento (final)

    ***Target start*:** Data de início

    ***Target end*:** Data Final

    Será preenchido de forma automática conforme planejamento ou restrições:

    ***Scheduled start*:** Início da programação

    ***Scheduled end*:** Final da programação

* + *Release* / *Sprint *(para equipes que utilizam Sprints para o planejamento de entregas)**.

5. **Gerencie** os itens e **Mantenha** o Plano atualizado:

* + **Avalie** na linha do tempo as entregas previstas;
  + **Verifique** se há *overbook* (mais itens do que cabem no *Release* ou *Sprint *(**para equipes que utilizam Sprints para o planejamento de entregas**)**);
  + **Atualize** as *issues* conforme o planejamento.

6. Também é possível criar **cenários** e compará-los para ver qual plano funciona melhor, por exemplo cadastrando os diferentes cenários conforme abaixo:

* + **Cenário A:**
    - Reduzir Escopo: Movendo as *issues* para o próximo release.

* + **Cenário B:**
    - Aumentar a Capacidade: Ajustando a velocidade ou adicionando pessoas ao *Dev Team*.

* + **Cenário C:**
    - Alterar as datas do *Release*.

* + Os cenários serão apresentados para que possam ser comparados:

**[Instrução de Trabalho - Como Criar um Plano no Portfólio for JIRA?](http://tdn.totvs.com/pages/viewpage.action?pageId=458767786)** *- Tópico "Como configurar cenários?"*

Estrutura do Portfólio

* **Iniciativa:**

* + Visão do Produto TOTVS;
  + Visão dos Projetos Estratégicos.

* **Programas:**

Algoritmo Padrão do Portfólio

O **Algoritmo Padrão** do *Portfólio*, considerará os seguintes aspectos:

* **Prioridade** do item no *Backlog* (*Rank*);
* **Estimativa** de *issues* (pontos);
* Atribuições dos ***Releases*** e ***Sprints** *(para equipes que utilizam Sprints para o planejamento de entregas)**;
* **Velocidade** do *Dev Team*;
* **Dependências** entre os itens do *Backlog*;
* **Restrições** configuráveis.

É possível realizar outras configurações (**não considerados no padrão**):

* **Disponibilidade** individual e do *Dev Team*;
* **Habilidade** das pessoas do *Dev Team*.
