#

| --- | --- |
| **Produto:** | TOTVS Gestão Contábil |
| **Versões:** | 12.1.22 |
| **Ocorrência:** | Alterações da ECD - Layout 7 |
| **Ambiente:** |  |
| **Passo a passo:** | **Definição do Processo:**  Este documento irá demonstrar todas as alterações que o layout 7 da ECD sofreu, visando os impactos dentro do TOTVS Gestão Contábil.  Para download do Manual da ECD (Escrituração Contábil Digital), acesse o link pelo site da Receita Federal do Brasil:  <http://sped.rfb.gov.br/pasta/show/1569>  **Alterações:**   * **Registro J801 - TERMO DE VERIFICAÇÃO PARA FINS DE SUBSTITUIÇÃO DA ECD**   **O registro J801** recebeu um novo campo **COD\_MOT\_SUBS** que irá armazenar o motivo da substituição. Estes campos recebem os seguintes códigos:  001 – Mudanças de saldos das contas que não podem ser realizadas por meio de lançamentos extemporâneos;   002 –Alteração de assinatura;   003 – Alteração de demonstrações contábeis;  004 - Alteração da forma de escrituração contábil;  005 – Alteração do número do livro;  099 – Outros.  **Impacto para o usuário no sistema**: Quando a escrituração for uma escrituração substituta, na geração do arquivo da ECD , na tela onde é selecionado o registro J801 será apresentado este campo conforme tabela do manual com os códigos citados acima.     * **Registro J930** - **SIGNATÁRIOS DA ESCRITURAÇÃO**   Os “Signatários da Escrituração” que identificava todos os signatários da escrituração bem como os do termo de substituição passou a mostrar apenas os **signatários da escrituração.**  Assim foi criado o registro **J932** que identifica os signatários do **Termo de Verificação para Fins de Substituição da ECD.**  **Impacto para o usuário no sistema:** Sem impacto para o usuário, apenas alteração do código fonte do sistema.     * **Registro J932 - SIGNATÁRIOS DO TERMO DE VERIFICAÇÃO PARA FINS DE SUSBTITUIÇÃO DA ECD**   Este registro é novo e internamente. A fonte de dados que está sendo utilizada para geração é a mesma do registro J930 pois os campos tem o mesmo conteúdo.  **Impacto para o usuário no sistema:** Sem impacto para o usuário, apenas alteração do código fonte do sistema.  **Importante:** O sistema irá verificar no momento da geração da escrituração substituta se na lista de signatários foi selecionado pelo menos um signatário do tipo (910), assim quando a escrituração é do tipo substituta o sistema adicionará ao arquivo o registro J932 bem como o J930.  Cadastrar o signatário dentro da Escrituração Contábil ( Obrigações Acessórias / Cadastros / Escriturações Contábeis):       * **Registro J935 - Identificação dos Auditores Independentes**   Este registro ganhou um novo campo para armazenar o CPF ou CNPJ do auditor independente.  **Impacto no sistema**:  Dentro do menu Obrigações Acessórias/Cadastros/Auditores Independente foi disponibilizado o campo “CPF ou CNPJ”  Obs. Para visualizar este campo, deverá solicitar a equipe do Suporte que disponibilize o script.       * **Registro J100 - Balanço Patrimonial**   Este registro ganhou dois campos novos (IND\_COD\_AGL e COD\_AGL\_SUP) outros dois campos foram renomeados e ganharam um ‘par*’.*  São eles VL\_CTA que agora tem o VL\_CTA\_INI e o VL\_CTA\_FIN e o IND\_DC\_BAL que é representado pelos campos IND\_DC\_CTA\_INI e o IND\_DC\_CTA\_FIM. Desta forma os campos VL\_CTA, IND\_DC\_BAL e IND\_DC\_BAL\_INI foram substituídos pelos novos campos.  **OBS:** O campo de nota explicativa não será mais utilizado para armazenar o resumo da nota explicativa e sim a numeração da nota explicativa referente a demonstração. Essa nota explicativa fica armazenada no registro J800.  **Impacto no sistema**:  Com relação ao registro J100 não houve impacto para o usuário, apenas alteração do código fonte do sistema.  Com relação às notas explicativas deverá ser informado a referência da nota explicativa e não mais o resumo da nota.  No J800 quando o tipo de documento for do tipo “Notas Explicativas” deverá constar a referência das notas explicativas.  **Pela Demonstração Contábil:**      **Pelo Plano de Contas:** Ainda não foi implementado.    **No J800:**  Criar o arquivo com extensão RTF e referenciar de acordo com o informado nas Demonstrações:       * **Registro J150 - Demonstração do Resultado do Exercício (DRE)**   Este registro ganhou três campos novos (IND\_COD\_AGL, COD\_AGL\_SUP e IND\_GRP\_DRE).  O campo IND\_VL foi substituído pelo campo IND\_DC\_CTA, neste novo campo os valores admitidos são apenas [“D”, “C”].  Os campos VL\_CTA\_ULT\_DRE e IND\_VL\_ULT\_DRE **foram removidos** no novo layout.  O campo **NOTA\_EXP\_REF** não será mais utilizado para armazenar o resumo da nota explicativa e sim **a numeração da nota explicativa** referente a demonstração.  Essa nota explicativa fica armazenada no registro J800.  **Impacto no sistema**:  Não houve impacto para o usuário, apenas alteração do código fonte do sistema.     * **Registro J210 - DLPA – Demonstração de Lucros ou Prejuízos Acumulados/DMPL – Demonstração de Mutações do Patrimônio Líquido**   **O registro J210** teve dois campos que foram renomeados e ganharam um ‘par*’.* São eles VL\_CTA que agora tem o VL\_CTA\_INI e VL\_CTA\_FIN e o campo IND\_DC\_CTA que agora tem o IND\_DC\_CTA\_INI e IND\_DC\_CTA\_FIN.  As regras do registro que foram adicionadas entram na mesma situação do registro J150. Eram regras já existentes que foram estendidas para ser a regra para o saldo inicial e saldo final por exemplo.  No registro também tem o campo de nota explicativa e vale a mesma regra para conteúdo e validação dos registros J100 e J150.  **Impacto no sistema**:  Não houve impacto para o usuário, apenas alteração do código fonte do sistema.     * **Registro J215 - Fato Contábil que Altera a Conta Lucros Acumulados ou a Conta Prejuízos Acumulados ou Todo o Patrimônio Líquido**   **O registro J215** teve apenas a adição de um novo campo DESC\_FAT que irá armazenar o nome do fato contábil.  **Impacto no sistema**:  Não houve impacto para o usuário, apenas alteração do código fonte do sistema.    **Registro I200 – Inclusão de novo tipo de lançamento – Tipo X – Lançamento Extemporâneo**  **Tipo X:** O tipo X deve ser utilizado para identificar lançamentos extemporâneos, que abrangem, entre outros, os lançamentos previstos nos itens 31 a 36 da Interpretação Técnica Geral (ITG) 2000 (R1) - Escrituração Contábil, do Conselho Federal de Contabilidade, publicada em 12 de dezembro de 2014.  Junto com este novo tipo de lançamento o registro ganhou também um novo campo “DT\_LCTO\_EXT”.  Neste campo deverá ser informado a data de ocorrência dos fatos, objeto do lançamento extemporâneo.  Caso não seja possível precisar a data a que se refiram os fatos do lançamento extemporâneo, informar a data de encerramento do exercício em que ocorreram esses fatos.  **Impacto no sistema:** Foi implementado na partida contábil o campo **“Data Extemporânea”.**  Para acessar este campo deve-se editar a partida, acessar a aba **“SPED Contábil”** e no campo **“Ajustes de Exercícios Anteriores”** informar a data extemporânea, ou seja, informar a data de ocorrência do fato objeto do lançamento, data em ocorreu o fato que está sendo retificado/corrigido.  Obs. Para visualizar este campo, deverá solicitar a equipe do Suporte que disponibilize o script. |
| **Observações:** | Lembrando que o layout 7 da ECD foi disponibilizado a partir das versões abaixo:  12.1.21.215 - ou superior; 12.1.22.191 - ou superior; 12.1.23.125 - ou superior e 12.1.24. |
