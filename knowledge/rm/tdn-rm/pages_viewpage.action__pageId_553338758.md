5%90%10%100%INTRODUÇÃO

As demandas de UX Design poderão ser registradas no JIRA em um projeto específico que será utilizado pelos times de UX de cada Segmento. 

Para os usuários que possuem acesso ao JIRA poderão registrar as demandas diretamente no Projeto, identificando qual é o projeto de seu segmento ou área e poderão registrar as demandas conforme as dicas que estão detalhadas.

Ao abrir uma demanda para o time de UX, é importante que o *Product Owner* (solicitante) consiga responder algumas questões na descrição da solicitação, como: 

**Qual é o problema que queremos resolver?**

Descrever qual problema foi identificado, se já existir algum chamado de cliente que complemente, pode ser anexado a *issue*. 

**Quais são os objetivos?**

Quais são os resultados esperados com essa tarefa, se há métricas para comparação, é interessante mencionar.  

**Qual é o publico alvo?**

Quem são nossos usuários/personas e quem queremos atingir com este projeto, contato de clientes para entrevistas sempre são bem vindos.

Também é importante destacar quem será ponto de referência do projeto, se o próprio *Product Owner* ou outra pessoa, e qual a expectativa de entrega do projeto por parte do time de UX para coincidir com a do time de desenvolvimento. 

**Fluxo de UX na Ferramenta JIRA:**

Para registrar as demandas no Projeto teremos as seguintes configurações:

**Tarefa:** Utilizada para registrar a demanda; Issuetype:Task;

**Epic**: Utilizada para agrupar as demandas do tipo Task;

**Subtarefas**: Para cada tarefa podem ser criadas atividades conforme a necessidade, as subtarefas são: **Entendimento do problema, Pesquisa, Co-criação, Prototipação, Validação, Documentação, Acompanhamento e Retrabalho UX Design.**

* **Considerações:**
  + O Fluxo é aberto onde é possível após passar pela etapa de *backlog* pular ou voltar etapas.
  + É possível criar as subtarefas em qualquer etapa do processo.
  + É sugerido criar um quadro *Kanban* na ferramenta para acompanhamento das demandas do time.
  + Outra sugestão é *linkar* as atividades pendentes no Projeto de UX Design as atividades do time, para que seja feito o acompanhamento;

**Importante:**

Para criar os projetos nesse template é necessário abrir *ticket* para o time de Suport Ops Desenvolvimento: **[eng.corp.desenv@totvs.com.br](mailto:eng.corp.desenv@totvs.com.br)**;

PLANEJAMENTO

Nessa etapa é realizado uma reunião com o time que demandou a solicitação para o entendimento da necessidade.

DESCOBERTA

É o momento onde deve se aprofundar nas regras do negócio, descobrindo quem são as personas. É onde aparecem mais incertezas no processo.

Abaixo alguma das ferramentas que **podem** ser utilizadas nesta etapa : 

* Desk Research *(estimar tempo);*
* Benchmark;
* Personas;
* Mapa de empatia;
* Matriz CSD
* Jornada de Usuário;
* Roteiro de Entrevistas;
* Agendar Entrevistas;
* Executar Entrevistas (presencial ou por telefone);
* Transcrever Entrevistas;
* Sintetizar dados coletados;
* Checkpoints com a *Squad;*
* Documentar.
DEFINIÇÃO

Na etapa de definição, é onde já entende-se o problema, e a participação do time é fundamental pois é onde será definido qual caminho deve ser seguido para a solução.

Onde podem aparecer mais de uma alternativa?

Abaixo alguma das ferramentas que **podem** ser utilizadas nesta etapa :

* Apresentação e Análise dos dados das entrevistas;
* Co-criações;
* Prototipação em papel;
* Personas;
* Jornadas de usuário;
* Mapa de Proposta de valor;
* Checkpoints com a *Squad*;
* Documentar.
CRIAÇÃO

O desenvolvimento de UX não envolve código, aqui é onde deve ser especificado e detalhado o protótipo ou qualquer que seja o entregável do projeto.

Abaixo alguma das ferramentas que **podem** ser utilizadas nesta etapa:

* Prototipação *(dimensionar tamanho/tempo P,M,G);*
* Mapa de navegação;
* Checkpoints com a *Squad*;
* Documentar.
VALIDAÇÃO

Na etapa de testes é avaliado tanto se a solução de fato atende e resolve o problema do usuário, como também deve ser testado a usabilidade do protótipo e de alguma proposta de interface que seja muito diferente do repertório do usuário.

Abaixo alguma das ferramentas que **podem** ser utilizadas nesta etapa: 

* Objetivo do teste;
* Roteiro do Teste;
* Agendar o teste;
* Executar o teste (presencial ou remoto);
* Fazer as alterações necessárias;
* Refazer os testes;
* Checkpoint com a *Squad*;
* Documentar.
ENTREGA

Após vários testes, deve ser entregue o projeto para o time ou solicitante e então se inicia-se a etapa de layout pelo UI Design e codificação pelos desenvolvedores.

Abaixo alguma das ferramentas que **podem** ser utilizadas nesta etapa:

* Síntese do projeto;
* Materiais e entregáveis que são relevantes para o time.
ACOMPANHAMENTO

Após a entrega é importante manter um relacionamento próximo com os times para acompanhar o desenvolvimento da solução. O acompanhamento pode ocorrer nas etapas de UI Design e QA.
