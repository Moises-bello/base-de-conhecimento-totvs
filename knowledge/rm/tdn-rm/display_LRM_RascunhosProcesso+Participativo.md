### Conceito

10%90%

O **Processo Participativo** consiste em uma demanda importante/estratégica, solicitada por um ou mais clientes, no produto padrão. Ela é antecipada por meio do desenvolvimento de um **Participativo** onde o investimento ocorre por parte do Cliente e da TOTVS.

As vantagens são para ambas as partes: a TOTVS entende que a funcionalidade agregará ao produto padrão, já o cliente se exime do custo de manter um produto específico.

### Detalhamento

Atendimento

O **Processo Participativo** inicia-se a partir de um ticket aberto por um cliente solicitando melhoria no produto padrão. O time de Atendimento analisa o ticket e, caso seja realmente uma melhoria, cria uma issue de melhoria para o time de desenvolvimento. Caso a **demanda não seja de melhoria**, a área de Atendimento deve analisar / triar / direcionar a demanda seguindo o **[Processo de Atendimento](http://tdn.totvs.com/display/NPROC/Home+Processo+de+Atendimento)**.

***\* Obrigatório***

Desenvolvimento

As demandas enviadas para o desenvolvimento, via ticket, são analisadas pelo *Product Owner* (que pode ou não contar com o apoio do time). Após analisar a melhoria, há três caminhos possíveis a serem seguidos:

1. **Customização específica:**Quando a demanda se trata de uma customização específica, é necessário direcioná-la para a Fábrica de Software para análise.
2. **Via backlog**: Quando a melhoria solicitada já está prevista para ser liberada via backlog, deve-se comunicar o cliente.
3. **Participativo:** Quando a demanda é considerada importante ou estratégica, e não está prevista em backlog, é oferecido ao cliente a possibilidade de desenvolver um Participativo.

   Caso ele não aceite, a melhoria é registrada no Banco de Ideias da TOTVS e comunica-se o cliente que a demanda será realizada via Backlog.

   Caso ele aceite, o PO deve, com a ajuda do time, refinar o escopo/esforço da demanda e comunicar a área responsável pelo faturamento do Participativo.

**Importante:** Qualquer melhoria deve ser desenvolvida na última versão / release vigente ou na versão em desenvolvimento. Assim, caso o cliente ainda não esteja utilizando a última versão / release, esta atualização deve ser prevista. Caso o Cliente queira um pacote compatível com a versão anterior, deve ser feita uma análise de compatibilidade pelo time TOTVS e haverá custo adicional para o Cliente para cada réplica que se fizer necessária entre a versão atual e a versão do Cliente. O calendário de expiração e o calendário de novos releases estão disponíveis no Portal do Cliente | Ciclo de Vida de Software (**[suporte.totvs.com/ciclodevida](http://suporte.totvs.com/ciclodevida)**).

Após **Faturamento do Participativo**, a demanda é incluída no *Backlog* e segue-se o **[Processo de Desenvolvimento Ágil](http://tdn.totvs.com/pages/viewpage.action?pageId=274831382)**.

***\* Obrigatório***

Faturamento do Participativo

A área responsável pelo **Faturamento do Participativo** recebe o refinamento de escopo/esforço do *Product Owner* e, com base nessas informações, elaborar a proposta.

Caso o clientes aceite, é necessário faturar a proposta para que possa dar início ao **[Processo de Desenvolvimento Ágil](http://tdn.totvs.com/pages/viewpage.action?pageId=274831382)**.
