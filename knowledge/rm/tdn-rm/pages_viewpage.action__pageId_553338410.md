1. As *Squads* devem acompanhar o retorno do cliente quando houver a liberação de uma Liberação de Pacote Emergencial. O Cliente pode retornar reportando que este pacote de correção não solucionou seu problema.
2. Antes de concluir a *Issue* (Manutenção / Legislação / Ponto de Entrada) deve ser avaliado o campo **Último Comentário Zendesk** e na aba **Zendesk** o texto informado pelo Cliente.
3. Caso o cliente **rejeite a Liberação Emergencial solicitando um ajuste**, siga as orientações abaixo:

   1. **Issue pendente com a *Squad*:** Enquanto a issue estiver nas etapas de atuação da área de desenvolvimento e a equipe for a responsável pelo contato com o cliente, deve-se abrir uma **subtarefa de Defeito e seguir o processo normalmente.**
   2. **Issue finalizada pela *Squad*:** Quando a issue estiver com os status Pronto para Expedição (Fluxo antigo) ou em Teste Integrado Concluído (Fluxo Novo), a área de Atendimento deve **abrir uma nova issue do tipo Rejeição – Manutenção** vinculada ao ticket inicial do Cliente. Com a utilização desta *issue type* é possível registrar e monitorar os retrabalhos gerados para o desenvolvimento.
   3. Caso o cliente **rejeite o *ticket* reportando outro problema**, a área de Atendimento deve **orientar o Cliente na abertura de outro *ticket*.**
